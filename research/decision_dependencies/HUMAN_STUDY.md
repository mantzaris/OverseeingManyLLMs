# Focused interaction study to prepare, not conduct, next

No participants were recruited and no human observations are included in this
package. The current evidence can establish scope mistakes, artifact correctness,
additional question demand and machine consistency. It cannot establish reduced
mental workload or improved perceived control.

The next useful interaction task is a trip or small analysis project with
preferences the participant supplies and can revise. Compare a strong shared
history/memory interface with the same evidence cards plus explicit decision
scope and change-impact receipts. Use the simple global release check in both
conditions when testing the interface. Otherwise a software correctness advantage
would be confounded with a presentation advantage.

Use a within-person crossover with low and high request demand, counterbalanced
condition and task order, and disjoint but matched task packets. Each packet has
ordinary reusable answers, one genuinely different exception and one instruction
change. Include stable periods and requests that need no new decision. Do not
force every request to be wrong or every change to favor the new interface.
Participants need everyday planning competence, not HVAC expertise. Record
experience with agent tools and stratify only if the eventual sample supports it.

Primary outcomes should be correct completed project artifacts and the number of
additional user responses. Analyze scope errors, stale releases, time to recover
after a revision, unnecessary confirmations and unresolved work separately.
Log actual card exposure, source inspections, deferrals, overrides and response
times. A shorter screen is not fewer decisions. Ask perceived-control questions
about understanding where an answer applies, correcting it and knowing which work
needs revalidation. Treat those as separate items unless a validated scale is
chosen before data collection.

Use the official [NASA Task Load Index](https://www.nasa.gov/human-systems-integration-division/nasa-task-load-index-tlx/)
for perceived workload, reporting its mental, physical and temporal demand,
performance, effort and frustration components. Prespecify whether raw unweighted
TLX or the weighted procedure is used. Do not infer those reports from token
counts, queue length or simulated response budgets.

Run a usability pilot first to identify instruction and logging failures. Estimate
within-person outcome variance and task-level clustering from actual pilot
interactions. Then select a smallest worthwhile effect and use simulation-based
power or precision analysis for the counterbalanced repeated-measures design.
Do not derive a participant sample size from the two GPU generations or 24 source
dialogues in this package. Freeze the human analysis, exclusion rules and sample
size before the main study, obtain required ethics review/consent, and retain
unfavorable and incomplete tasks.
