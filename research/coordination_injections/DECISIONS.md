# Development and adaptation log

## Initial choice

The inspection started from clean main at ecebc374. Existing results argue against
using consensus or versions as semantic correctness. Real recorded transactions
and a query -> chart -> numerical-claims chain offer actual output dependencies.
An independent appendix creates a checkable exception. Source audits are separate
from constructed requirement changes. Fixed data blocks, not retailers, are the
eventual paired units.

LLM-Flock's topology-weighted plan adoption is an inspiration, not a directly
applicable analytics algorithm. InstructFlow already injects symbolic execution
feedback into an instruction graph for local repair. AIPOM already supports user
goal changes, plan repair and dataflow updates. The useful distinguishing experiment
is therefore executable scoped adaptation versus strong shared-state and broadcast
controls, not claiming that packets, graphs or feedback are new.

## First competence probe and revision

The first fixed December development project used no hidden targets in prompts.
The analysis query sometimes omitted quantity>0; the appendix incorrectly filtered
country='ALL' and missing customers. Public synthetic probes caught these defects,
even when a wrong query happened to match the current real-data top five. Downstream
work stayed unfinished rather than being fabricated. The complete v1 artifacts and
calls remain saved.

Revision v2 expands each public reporting convention into concrete per-field
instructions. ALL is explicitly identified as a routing sentinel, inclusive/exclusive
date boundaries are explained, and both parts of the positive rule are stated.
These are user-contract definitions, not supplied final aggregate answers or reference
queries. Public probe feedback now includes its small constructed expected/observed
tables, clearly separated from real-data references. All methods get the same
expanded requirements and legitimate checks. No evaluation outcomes have been seen.

## Interface adaptation before freeze

The initial plan allowed two revisions. The SQL-to-tool change needed two additional small prompt repairs, exceeding that provisional development count. This is a documented development deviation, not a hidden evaluation repair. v3 and v4 were stopped and their completed requests retained: the model interpreted a missing old artifact as grounds to block or keep. v5 states that an absent/invalid artifact must be produced and limits `keep` to already valid work. No held-out generation had occurred. The protocol and user-authorized stage ceilings were unchanged.

The final interface uses generated query parameters compiled to SQL, chart prefix/source/unit selections and report source/unit selections with tool arithmetic. It does not establish competence at unrestricted SQL synthesis or arithmetic. Initial v5 projects now complete all four artifacts under current instructions. The deterministic parameterized pipeline is therefore essential: the application may be solved without any LLM, and routing cannot be credited for tool correctness.

## Frozen evaluation boundary

Commit `8935400b` records the final tool interface, routing rules, source snapshot, public/private checks, model settings and exact primary/secondary matrix before held-out generation. The collection source hash remains unchanged. Four development originals passed all four structured contracts. The forecast was about 41 minutes with a 50% latency margin for 760 new calls. The stage ceiling remains 1,600 scheduled calls and 2,000 attempt intents, counting every development revision.

Post-freeze work adds replay, plotting, a local interface and descriptive diagnostics. It does not alter the primary method. External API validation now rejects peer-authored instruction registrations and malformed protected-scope changes; all frozen projects already satisfy that validation. A reporting clarification labels stress-condition appendix rewrites as potentially necessary restoration, rather than claiming they were unnecessary merely because the contract was unaffected.
