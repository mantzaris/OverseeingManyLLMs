This is a source review, not a reproduction of the published systems. The implemented baselines are controlled adaptations of shared-state invalidation and message routing.

## What is being tested

The protocol extends executable, dependency-aware plan repair with an explicit trust boundary for user changes and scoped exceptions, followed by a bounded test of actual uptake. It asks whether routing those identical packets improves correctness or cost over competent global invalidation and broadcast. It does not implement influence-weighted flocking, a CONSENSAGENT optimizer, an AIPOM user study or InstructFlow's symbolic constraint induction. Those are conceptual comparisons.

The flocking vocabulary is only an interpretive analogy. Cohesion means compliance with applicable requirements. Alignment means compatible dependent artifacts. Separation means separate responsibilities and an independent evaluator. Steering means adaptation to an authorized change. None of these words supplies an algorithm or novelty claim.

The strongest competing explanation is **ordinary incremental recomputation with constrained tools**. If global checking matches targeted routing, recipient selection adds little. If the parameterized pipeline is perfect and cheaper, these reporting contracts do not establish a need for LLM agents. If gains appear only after injected disturbances, they establish a bounded recovery behavior rather than natural adaptation superiority. A positive routing result must survive identical packet content and unchanged acceptance rules. Any claims about users' effort require a later interaction study.
