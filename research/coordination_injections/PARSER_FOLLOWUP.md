# Separately declared parser-only follow-up

The primary study is complete and preserved. The failure audit shows that many report responses use an explicit `tool/params` envelope instead of the requested top-level shape. Their supplied source and unit can be usable. The strict parser rejects them before an artifact is produced. The final development originals all passed, but we did not diagnose this adaptation-specific envelope pattern before freezing. The primary shared-state disadvantage is therefore confounded by a preventable interface defect.

This follow-up changes only deterministic envelope normalization. It accepts the recognized role's tool and explicit parameters, including nested or flat representations. It does not insert a missing country, date, metric, source, unit or hidden answer. Conflicting representations and wrong tool names remain unsupported. Incorrect supplied values still face the same public guard. Every raw response is retained.

Use all sixteen already inspected primary projects at replica 0, five methods including the matched packet-format global control, and the same saved pre-change checkpoints. Generate actual fresh method-specific continuations. Never replay downstream responses from the strict-parser condition as counterfactual repaired trajectories. Keep the same model, seeds, prompts, tools, cap of two calls per role and two rounds. The only context differences arise from actual normalized outcomes and resulting histories. Limit this follow-up to 320 scheduled calls within the unchanged session ceiling of 1,600 calls and its existing cutoff. Expected use is about 260 calls.

Commit this plan, the manifest, normalization code and collection code before generation. Analyze paired monthly-block differences with the original bootstrap seed and report all five methods. These cases have already been inspected. This is a **post hoc exploratory sensitivity**, not a new held-out evaluation and not a replacement for the frozen primary result. If normalization removes the apparent benefit, attribute it to the interface repair and recommend the simpler controller. Do not use these results to tune another variant in this stage.
