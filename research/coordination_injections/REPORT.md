# Coordinated adaptation on recorded retail transactions

## Conclusion

The prototype supports one scoped requirement change followed by verified updates to a connected analysis table, chart and numerical report while preserving an appendix. The real-data experiment supports this **engineering protocol**, but not a distinctive recipient-selection advance over a competent global check. A preventable tool-envelope parsing problem confounded the initial quality comparison. A separately declared, fresh-generation follow-up makes that limitation visible instead of replacing the original result.

With compatible parsing, targeted and same-packet global checking each completed **16/16 structured projects in 46 calls**, with identical request sequences on all sixteen pairs. Active broadcast completed 16/16 in 64 calls. The deterministic pipeline completed every original project in zero model calls. For these fully specified reporting contracts, use the simpler parameterized pipeline or normalized global check. More elaborate routing is not justified by this evidence.

These conclusions concern executable numerical contracts, not all generated prose. A generated report called stock codes customers despite passing the numerical guard. The default interface displays checked numerical claims and explicit contract labels; raw prose remains inspectable and unvalidated.

All 541,909 recorded lines remain in the source snapshot. The audit found 5,268 duplicate rows beyond the first, 135,080 missing customer IDs, 1,454 missing descriptions, 10,624 negative quantities, 1,336 negative-quantity rows without cancellation markers, 2,515 zero prices and two negative prices. December 2011 is partial. Full audit, row transformation hash, formulas and conventions are in [DATA.md](DATA.md) and `data_audit.json`.

Development uses December 2010 and January 2011. The evaluation blocks are February through September 2011, containing 293,303 original rows before project-specific filters. There are **eight nonoverlapping monthly blocks from one retailer**, sixteen constructed projects and two generation replicas. These are not sixteen independent organizations. Month blocks may still be serially dependent. Two projects within each block share records and are averaged together with their replicas for inference.

The data are recorded transactions. Briefs, scopes, roles, changes and disturbances are authored. Tool plans and messages are generated by Qwen on the GPU. Query execution, plotting arithmetic, validation and scoring are deterministic. There are no participants, measured attention costs, actual business savings or empirically established revenue-recognition rules. Recorded quantity and line value are precisely defined reporting conventions, not profit.

## Protocol and competence

The analysis agent selects every query parameter; a constrained tool compiles executable SQL. The chart agent selects the actual analysis result, displayed prefix and unit. The reporting agent selects the chart and unit; tool arithmetic supplies numerical claims. An independently scoped appendix retains its original contract. Public checks verify parameters, actual execution, units, data dependencies and consumed instruction hashes. The evaluator independently aggregates real records in Python. It never selects packets or recipients.

Each continuation has two rounds and at most two calls per role. A failed or unchanged artifact remains unfinished. Peer notification can forward an immutable user packet only along registered dependencies. The external API validates scope exceptions and rejects peer authority and unsupported argument shapes. It is a local application trust boundary, not a network identity service.

Initial unrestricted SQL pilots failed basic filters. The development interface was narrowed to explicit tool parameters and exact tool arithmetic. Two small prompt repairs beyond the provisional two-revision plan were required because the model treated missing old outputs as reasons to block or keep. The failed and interrupted development runs are retained. All four final development originals, and all **32 frozen evaluation originals**, completed all four structured artifacts under complete current instructions. This demonstrates competence with the constrained tools, not unrestricted SQL synthesis.

The adaptation pilot still contained unsupported nested report envelopes. We failed to diagnose that pattern before the primary freeze. The subsequent parser audit and exploratory follow-up are essential to interpreting the result.

## Frozen primary study

Commit `8935400b` freezes the code, task list, model settings, checks, scope rules, limits and analysis before held-out generation. All methods receive the same authorized changes and permitted checks. Shared state inspects every role and repairs invalid work. Active broadcast sends the applicable correction to every agent and charges its model processing even when no change is needed. Targeted routing sends the same packet to changed-contract roles. Sparse routing starts at affected roots and allows model notification plus a bounded global fallback. A same-packet global control isolates presentation from routing. The zero-inference pipeline exposes the strength of ordinary parameter flow.

Every policy receives actual fresh continuations from its paired original checkpoint. No response from a different prompt substitutes for a counterfactual generation. Execution order rotates. The model and decoding settings stay fixed. All planned primary and secondary runs completed.

Targeted, sparse and global checking rewrote none in the ordinary condition. A rewrite can leave the numbers correct; it still changes artifact identity. Active broadcast's extra calls primarily charge processing of irrelevant notifications. Passive delivery followed by a global check is represented by the stronger global controls and avoids that charge.

## Parser audit and separately declared fresh follow-up

The static leaf-artifact audit recognized equivalent explicit envelopes in **16/18** unfinished reports. All sixteen recognized cases pass the same public checks and private numerical comparison after local normalization of that final report. This is an artifact diagnostic, not a replacement policy trajectory. Two remaining forms have conflicting fields or unsupported structures.

Commit `b9962231` declares the follow-up before new generation. It uses all sixteen already inspected projects at replica 0, five methods, unchanged prompts and checks, and the same saved originals. The normalizer accepts only recognized `tool/params` envelopes with explicit values, never obtains missing parameters from the contract or evaluator, and rejects conflicting representations. It does not relax numerical or scope checks. Every continuation is newly generated. This is **post hoc exploratory sensitivity**, not a fresh held-out sample.

The follow-up used **250 new calls**. Targeted-minus-broadcast remains -1.125 calls/project [-1.3125, -1.0000], with identical observed structured completion. Targeted-minus-same-packet-global is **zero for both completion and calls in every block**. A protocol audit goes further than a statistical tie. In this fixed, scope-complete graph, every initially invalid role is exactly a changed-contract role. Both targeted and same-packet global checking then use the same order and fallback. Their follow-up request sequences match in **16/16 projects**. They cannot demonstrate different recipient-selection value under these conditions. The additional repeated inspection in the global implementation is a small implementation redundancy, not a new asymptotic advantage.

## Mechanism, stress and failures

The separately frozen stress condition corrupts a protected appendix parameter and value in the same way for each method, on the first project of each month, replica 0. Structured project completions are **6/8 global state, 7/8 broadcast, 7/8 targeted, 7/8 sparse and 8/8 targeted without detailed issue feedback**. Calls are 38, 35, 35, 34 and 34 respectively. Targeted and sparse require two rounds because they restore the appendix during expansion; broadcast averages 1.375 rounds. Extra feedback does not establish a benefit here. Restoring this corrupted appendix is necessary even though its contract is unchanged, so these rewrites must not be called unnecessary repairs.

Eight fully authored mechanism cases (32 controlled runs, zero inference) cover shared and local changes, no change, delayed notifications, false acknowledgment, corrupted exceptions, correlated wrong definitions and irrelevant forwarding. The controller preserves unfinished work and rejects unsupported cycles. These cases test properties, not real-world prevalence. The ordinary real-data comparison was not created by injecting baseline-only faults.

Among 152 repeated identical primary/secondary request-payload groups, 11 vary in parsed output text. One varies in envelope shape and therefore in strict-parser acceptance. After recognizing equivalent envelopes, **1 group differs in normalized tool representation**: a different May request returns a tool-description string without arguments in one run, and explicit usable arguments in the other. Thus normalization removes the April envelope difference but not every consequential output failure. Neither pair shows two distinct valid numerical parameter selections. Identical seeds do not promise bitwise reproducibility. Different prompts produced by changed dependencies remain a separate phenomenon. Saved-output replay is deterministic.

A post hoc narrative audit found four accepted structured reports for `eval_06_0`, replica 0, describing stock codes as customers. The same error appears under all four policies. This does not invalidate the prespecified numerical score, but it rules out describing that score as complete free-text correctness. The prototype keeps this generated prose in the evidence view and renders checked quantities with explicit schema/contract labels in the normal report card.

## What is and is not new

[AIPOM](https://aclanthology.org/2025.emnlp-demos.7/) already supports user edits, agent-plan repair and downstream reruns. [InstructFlow](https://papers.nips.cc/paper_files/paper/2025/file/03cfff3eccb29aa15f76e9bcee3d1be7-Paper-Conference.pdf) already uses execution feedback for graph-guided correction. Blackboard systems, event-triggered communication and incremental build systems supply other close mechanisms. [LITERATURE.md](LITERATURE.md) records the inspected sections, current versions and code availability.

The implemented contribution is an explicit scoped execution protocol, a public/private checking boundary, and a controlled real-data application that exposes parser, routing and tool effects separately. It is **not** a demonstrated new routing algorithm, a stability theorem, a measured reduction in human workload or evidence that multiple LLM agents improve this standardized analysis over a pipeline. Generic flocking terms do not change that assessment.

## Resource accounting and limitations

The stage started **2026-09-12 01:49:39 UTC**, with a **04:49:39 deadline** and **04:04:39 inference cutoff**. The original 36-hour window had already expired; its timestamps and historical commands remain unchanged. Stage and cumulative wall time, including inter-session gaps, are recorded in `resource_ledger.json`.

Inference totals are final: **1,316 scheduled calls, 1,315 attempt intents, 1,314 returned successful responses, zero transport retries and zero returned HTTP failures**. Two development requests were interrupted: one before a generation intent, and one after an intent whose response was not retained. The latter is charged as an attempt with unknown tokens. Known usage is **874,657 prompt and 112,851 completion tokens**, 987,508 total; at most one 2,048-token context worth of usage is unobserved. Returned generation latency sums to **2545.18 seconds**, not human response time or GPU billing duration. The main frozen study uses 803 calls; the parser follow-up uses 250; development accounts for the remainder.

At the report accounting checkpoint (2026-09-12T03:44:27.351032+00:00), stage wall time is 1.913 hours. Cumulative wall time from the original start is 60.092 hours, including inter-session gaps, or 24.092 hours beyond the historical 36-hour target. Cumulative accounting is 58,674 scheduled calls and 58,669 attempt intents. The final closing ledger records any later verification and commit overhead.

The existing RTX 6000 Ada server and cached pinned model were reused. Actual runtime is Python 3.11.13, PyTorch 2.8.0+cu128, CUDA runtime 12.8, Transformers 4.55.2 and vLLM 0.10.2. BF16 support and GPU engine allocation were checked. All generation used this GPU with zero CPU offload. Local orchestration uses Python 3.8.10. No paid resource was provisioned, no model was retrained and no participant or maintainer was contacted. Pod price and billed allocation are unavailable. Temporary local workers are stopped at completion; the existing model server is preserved.

The limited task space, explicit scope registration, single retailer, dependent month blocks, small paired sample, shared model across roles and unchecked prose constrain generalization. The data do not establish observed user workloads, repair benefit, accounting profit or semantic correctness of arbitrary instructions. The parser follow-up is exploratory and must remain separate from the frozen comparison.

**Recommendation:** keep the practical scoped tool-and-state implementation, simplify to normalized global checking or the parameterized pipeline for this application, and do not make recipient routing the paper's central contribution. The next useful experiment is schema- and provenance-linked verification of generated narrative claims on new analytics tasks. The observed stock-code/customer confusion is a concrete unsolved problem; another queue or routing variation is not justified by this study.
