# TAT-QA provenance and construction

Source: https://github.com/NExTplusplus/tat-qa at 870accc41953dcde885aabeb963d94aabdc0fbc3. Original publication: Zhu et al., TAT-QA, ACL-IJCNLP 2021, DOI 10.18653/v1/2021.acl-long.254. Dataset attribution/license: CC BY 4.0 according to the upstream README. Released implementation: MIT. `artifacts/adaptive_correction_transfer/provenance.json` records exact source and evaluation-code hashes. Raw upstream data remain outside Git; a pinned download command is supplied with reproduction.

The source financial tables and accompanying prose come from real reports. Questions and annotations were produced for the benchmark by finance-trained annotators. Constructed here are assignments to agents, inspection episodes, budgets and annotation-based supervision. Model answers and repairs are generated. This is not an observation of users supervising agents.

The released raw train/dev/test_gold files have 2201/278/277 contexts and 13215/1668/1663 questions. Public test_gold was released in January 2024. The unlabeled test file has one additional context and six additional questions; unavailable annotations are not invented. The original benchmark split is by context. Raw records provide table and paragraph UUIDs, but no reliable report identifier. We therefore use source context as the paired unit and explicitly retain the possibility of dependence between different contexts from the same report.

Technical eligibility is source-order, four to eight original questions and a bounded source length. Exact normalized table or full-context duplicates across released train, dev, and test_gold order are excluded. `source_audit.json` preserves every eligibility decision and duplicate hash. The first twelve eligible train contexts were used for development, including all prompt revisions and failures. Evaluation uses previously uninspected public test_gold contexts selected before generation. No performance-based replacement is allowed.

Question wording and source values are retained. Table formatting uses Markdown with row Tn and column Cn identifiers; literal vertical bars are rendered as slashes to preserve the table interface. Paragraphs receive their original order labels. Answers, scales, derivations, answer types, and any annotated mappings are excluded from the public projection. Test_gold contains additional mappings/facts; these are not treated as complete human-verified evidence alignments and are never controller features.

The official exact-match and token-F1 implementation is vendored with its license. Only its local import path is changed. Official normalized answer scoring incorporates scale; exact scale agreement and joint answer/scale correctness are reported separately. Evaluator failures and malformed outputs score zero. Arithmetic execution is allowed only when the model explicitly selects an expression as its answer; an intermediate calculation cannot overwrite an answer such as a year.

Each context's existing questions are distinct benchmark tasks. No duplicate artifacts are introduced to manufacture transfer utility. Shared source alone does not establish a shared correctable error. Evidence compatibility is inferred from generated citations and question text, and transfer is measured rather than assumed.

A second public-material audit checks exact normalized tables and repeated paragraphs of at least 160 normalized characters within the selected evaluation set. Its results are in `analysis/source_dependence.json`. Such overlap does not supply a missing report identity, and its absence would not prove independent reports. The main uncertainty intervals retain their declared context-level, descriptive interpretation.

Reporting clarification after freeze: unparseable JSON and empty answers receive zero, but the official metric can credit a readable extracted answer even when a parser flag marks an auxiliary or scale-schema field invalid. Unsupported scale tokens are reset to the empty scale and flagged, without consulting a reference. Thus the broad frozen phrase "malformed outputs score zero" overstates the implementation. Primary scoring and acquired-label updates are preserved; `contract_audit.json` enumerates these cases and a post hoc strict-schema rescore reports the effect separately. That rescore is not a regenerated policy evaluation under different online labels.
