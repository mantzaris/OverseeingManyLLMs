# Closest literature and verified distinctions

Checked 2026-09-11 against primary full texts and author repositories. Read methods
and evaluation, not only abstracts. Checksums and repository commits are in
`artifacts/verification_escalation/provenance.json`. Published venues below are
verified independently of repository claims where a proceedings record exists.

| Work, latest inspected version | Mechanism and supporting section | Evaluation and available assets | What this exploration adds or does not add |
|---|---|---|---|
| [AmbiQT / LogicalBeam](https://aclanthology.org/2023.emnlp-main.436/), EMNLP 2023, arXiv v1 | Sections 3 and 5 construct schema ambiguity and diversify SQL through plans and constrained infilling. | Spider questions with constructed schemas, partly ChatGPT-generated synonyms. [Author code and data](https://github.com/testzer0/AmbiQT), MIT. Evaluator maps alternatives back to original SQL. | Multiple interpretations are established. Mapping both alternatives to original data cannot demonstrate practical equality of their consequences. We do not use this as an empirical verification win. |
| [AmbiSQL](https://arxiv.org/abs/2508.15276), v2 March 2026, SIGMOD Companion 2026 demo stated in full text | Sections 2.3-2.4 detect ambiguity, ask multiple-choice questions with Other/Abstain, update a preference tree, and iteratively rewrite requests. | The paper describes 40 annotated queries. [Code](https://github.com/JustinzjDing/AmbiSQL) has five frontend examples and BIRD download instructions, but no complete reference table in the inspected tree. `sql_diff_detector.py` uses an LLM to describe structural differences. | Scoped reuse and iterative clarification are not new. We separately execute output comparisons and expose their conditional boundary; we do not reproduce XiYan-SQL or the paper's evaluation. |
| [PRACTIQ](https://aclanthology.org/2025.naacl-long.13/), NAACL 2025, arXiv v2 January 2026 | Section 3.2.1 already avoids some clarification by returning helpful SQL that covers alternative columns. Sections 3.1-3.3 construct and check ambiguous/unanswerable conversations. | Model-generated database changes and dialogue around Spider; human quality checks. [Author repository](https://github.com/amazon-science/conversational-ambiguous-unanswerable-text2sql) provides the generation pipeline, archived July 2026. No complete prepared task set in inspected tree. | Avoiding unnecessary questions is established. A wider result containing all interpretations differs from a fixed-contract table that is unchanged across interpretations. Neither implies measured attention savings. |
| [BIRD-Interact](https://arxiv.org/abs/2510.05318), ICLR 2026, current full text | Sections 2-3 and interaction environments support knowledge retrieval, ambiguity resolution, execution recovery and related follow-up tasks. Knowledge ambiguities are deliberately injected. | PostgreSQL benchmarks, expert annotations and function-driven user simulation. [Repository](https://github.com/bird-bench/BIRD-Interact). [Current full-data card](https://huggingface.co/datasets/birdsql/bird-interact-full/blob/main/README.md) still requires email for reference SQL/tests. | Retrieval before asking and executable feedback are established. We did not request assets or claim a BIRD result. Our explicit-dependency tests do not establish naturally shared decisions in BIRD. |
| [KnowNo](https://proceedings.mlr.press/v229/ren23a.html), CoRL 2023, arXiv v2 | Sections 2-3 form prediction sets with a held-out conformal calibration set and request help when multiple actions remain. An unlisted-option category addresses candidate omission. | Simulated and real-robot tasks. [Author code](https://github.com/google-research/google-research/tree/master/language_model_uncertainty). | Set-valued uncertainty and selective help are established. Our simple candidate safeguards have no conformal guarantee. Coincident outputs cannot replace calibration or evidence that intended interpretations are covered. |
| [Value of Information](https://aclanthology.org/2026.acl-long.1987/), ACL 2026 | Sections 3, 4.1-4.2 formalize clarify-or-commit, estimate response beliefs and compare expected utility gain against communication cost. | Four task domains with simulated interaction; [author code](https://github.com/dong-river/VOI_communication). | Consequence-aware clarification is established. We substitute bounded executable comparisons for estimated utility in a restricted snapshot-table contract. We do not reproduce its full response model. |
| [AMBROSIA](https://arxiv.org/abs/2406.19073), NeurIPS 2024 Datasets and Benchmarks, v2 | Sections 3.1-3.4 define ambiguity persisting with database context, generate databases and obtain human-written questions/interpretations. Section 4 evaluates interpretation recovery. | 846 generated databases; human questions, template SQL for scope/attachment, human SQL for vagueness. [Code](https://github.com/saparina/ambrosia) and [public-password dataset](https://ambrosia-benchmark.github.io/), CC BY 4.0. | This is the chosen external benchmark. It deliberately contains consequential ambiguity and cannot establish the prevalence of harmless uncertainty in everyday agent work. |
| [Disambiguate First, Parse Later](https://aclanthology.org/2025.findings-acl.863/), Findings ACL 2025 | Sections 2.3-2.5 use execution comparison to identify missing interpretations, train an infilling model and remove redundant outputs. | AMBROSIA and AmbiQT; [code, checkpoints and outputs](https://github.com/saparina/disambiguate-then-parse). | Execution-based interpretation coverage and deduplication are already established. Our untrained second generation pass is not their learned infiller and must not be named as a reproduction. |
| [Sphinteract](https://www.vldb.org/pvldb/vol18/p1145-zhao.pdf), PVLDB 18(4), 2024 | Sections 4-5 and Algorithm 1 use Summarize, Review, Ask and an early-stopping option. | KaggleDBQA and BIRD plus actual participant studies; [author artifacts](https://github.com/ZhaoFuheng/Sphinteract). | Selective clarification and early stopping are established. Unlike our scripted desk, this paper contains human interaction evidence. |
| [SOMA-SQL](https://arxiv.org/abs/2606.11424), v1 June 2026 preprint | Sections 3.2-3.5 use multiple candidates, taxonomy-guided ambiguity discovery, synthetic query-log retrieval and targeted execution probes to infer intent and repair SQL. Section 4.4 compares probing with voting. | Six benchmarks; detailed prompts in appendices. No author code release linked in the inspected paper/landing page. | This is the strongest competing explanation for autonomous resolution. Our potential distinction is refusing to infer a preference solely from a plausible database pattern, instead conditionally releasing an invariant artifact or escalating. That is a protocol distinction, not proof of a new algorithm or superior performance. |

The existing reviews of multi-agent clarification, shared memory and audit allocation
remain relevant in `research/decision_dependencies/LITERATURE.md` and
`research/clarification_planning/LITERATURE.md`. This experiment adds no claim that
shared oversight, source recovery, execution checking, minimax regret or asking only
valuable questions is new. No full-text access failure occurred for the ten works
above. Some released-code paths guessed during inspection returned 404; repository
trees and verified paths, rather than those guesses, support the asset audit.
