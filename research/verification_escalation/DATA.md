# Source provenance, access and evaluation boundary

**Current principal set:** the ordering-correct follow-up contains 24 fresh
databases, eight per ambiguity type, with two replicas. It excludes all 57
databases used in the initial development and evaluation. Its paired source
availability subset has six databases. `repair/split_manifest.json` records all
IDs and exclusions. The paragraphs below also preserve the initial 48-database
selection, whose blanket unordered contract was subsequently found defective.
See REPAIR_PROTOCOL.md for the separate freeze and interpretation.

Primary source: AMBROSIA, Saparina and Lapata, NeurIPS 2024 Datasets and Benchmarks.
The full public-password archive contains 4,242 CSV rows on 846 databases. Human
annotators authored ambiguous requests and disambiguated interpretations. Databases
were generated by OpenChat and filtered by the source authors. SQL for scope and
attachment was template-generated; vague-query SQL was human-authored. These are
not observed production records or observations of people using our prototype.

The source-order rule takes one ambiguous request per database and three development
plus sixteen held-out test databases per ambiguity type. All 57 databases are
distinct. Source labels, reference SQL, clarifying utterances and ambiguity category
are evaluator-only until a specifically simulated answer is requested. Public
input contains the request and compact complete schema/rows. The current source
snapshot supplies no annotated cross-task shared decision. All multi-agent shared
workloads in this package are separately authored synthetic cases.

Reference annotations have two roles. They score returned snapshot tables and
provide the simulated user utterance after a charged answer. A precomputed GPU
response to that utterance is cached per replica. The controller cannot read that
cache until it asks. The privileged reference-candidate condition intentionally
uses reference SQL; it is a mechanism diagnostic, not operational model accuracy.

The source-recovery condition moves an existing human-written interpretation into
a prior scoped instruction for 12 of the same held-out cases. This is an authored
availability manipulation. It does not invent a new human response or imply that
the source collected multi-turn conversations. It is paired, not 12 new independent
source cases. Raw prompts contain these source texts and are retained locally.

The source website requests no GitHub/Hub dataset upload to discourage training
contamination, although its license is CC BY 4.0. Accordingly, the downloaded
archive, source cases and raw request/response envelopes stay excluded from Git.
Committed material includes selection IDs, checksums, generated candidate SQL,
provenance hashes, compact execution outcomes and reproducible analyses. This is
an explicit new publication-redaction decision. It neither alters nor reverses
historical publication-redaction records. Full evidence remains locally available
under the excluded `private/` and `raw/` directories. A clean checkout reconstructs
source inputs from the original public download and uses committed model outputs.

All source reference queries are checked after freezing, without changing the
sample. Foreign-key defects are documented even when unrelated tables do not affect
the requested SELECT. Our evaluator preserves row tuples, column order, duplicates
and NULL. The inspected upstream unordered comparison flattens cell values across
rows, so we use the stricter declared table contract instead of its comparator.
No official AMBROSIA score is claimed. Output agreement is weaker than semantic SQL
coverage; generated semantic labels may be inaccurate and are not independently
validated by a model judge. Coverage metrics mean reference-output coverage only.

Known access alternatives: AmbiQT is public with executable data, but mapped
schema synonyms can mechanically duplicate semantics. AmbiSQL currently publishes
five frontend examples, not the complete annotated 40-case dataset described in its
paper. PRACTIQ publishes a generation pipeline. BIRD-Interact reference SQL/tests
still require requesting access. No maintainer was contacted and no unavailable
asset was circumvented. See LITERATURE.md and provenance.json for exact revisions.

## Limits of source disjointness

The follow-up excludes all source databases previously inspected in this exploration.
That project-level exclusion is not evidence that the pinned model's training data
excluded this public benchmark. Domains and construction templates are reused, and
the source-database bootstrap does not create independence from those conventions.
