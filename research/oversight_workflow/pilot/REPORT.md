# Formative pilot preparation report

The investigators can now run a compact B/C pilot from one setup screen, preserve
all work at cutoff and analyze identified exports. This completes software and
study preparation, **not a human evaluation**. The central review protocol and
existing position-paper manuscript remain unchanged.

## Task feasibility finding

The task material is usable for a **formative feasibility study**, with a substantial
risk that review becomes reconstruction. The full offline audit retains all 290
initial answers from 24 TAT-QA contexts and the original scores. Seven of the 38
empty answers were nested arrays lost in parsing. A uniform pilot-only projection
restores those components, leaving 31 empty/unsupported answer fields. Eight of the 24 explicit-empty
responses still contain answer-bearing text elsewhere; four contain partial or
qualified text. The raw-response expansion preserves such material without
promoting it into a scored answer. The source-only check must therefore test actual
draft usefulness, which exact match alone cannot establish. Exact match remains
**61/290** and joint answer/scale correctness **59/290**. The projection improves
readability, not demonstrated correctness. The evidence-format flag appears on 157
answers, including 32 jointly correct answers, so it must not be equated with error.

A declared 22-case nonempty audit includes 10 correct controls and 12 scored errors.
Nine error cases have clear content or unit problems; three have plausible
interpretation, scale-annotation or source-rounding disputes. These are developer
assessments, not independent adjudications, and the stratified sample cannot estimate
the prevalence of these causes over all 229 nonmatches. No semantic score was
substituted for official scoring. [AUDIT.md](AUDIT.md) and exact case files preserve
the raw-to-display path, annotations and unresolved assessments.

The final public-selection packets contain 36 original questions from six source
contexts: 7 exact/joint correct drafts and 5 missing drafts in replica 0. No packet
was chosen because of a model outcome. Source lengths are 3,344/3,144/3,240 characters,
table sizes 57/69/57 cells per packet and arithmetic-wording counts 7/6/6. A source
question whose wording refers to pension obligations while its table emphasizes
asset allocation remains visible and flagged only in the investigator audit.
It illustrates why source-only feasibility and blinded adjudication are needed.
No new inference was justified by the audit; there were **zero new generations**.

## What changed

The existing desk now has a thin, versioned pilot wrapper, not a new queue engine.
It provides pseudonymous setup, 18 counterbalanced assignments, separate training,
two nine-minute B/C blocks, a four-minute source-only block, a calculator, visible
timer, complete forms and identified export. Setup controls remain outside scored
views. A deferred uncommitted answer, its scale and note return together. Missing
answers are explicitly described; the user can write, reject or defer, and cannot
approve a nonexistent answer through the pilot UI. Approval still needs a separate
exact-version release. C's optional source-session controls are placed above the
long source display so they can be found without scrolling past the entire source.

Common B/C features include the exact outputs, source access, calculator, stable
active review, individual decisions, unfinished-work accounting and release rules.
**C adds source sessions, session-aware Next selection, and pause/resume of new
starts.** This is an interpretable workflow-bundle comparison, not a causal isolation
of one button. Neither condition is presented as better in the neutral script.
No revisions, model errors or business deadlines were artificially inserted into
scored packets. Software boundary fixtures remain separate.

A source-only diagnostic uses a third, disjoint packet. It can reveal source and
calculation difficulty and whether drafts add useful assistance or more checking.
Its position rotates, and participants never see the same source twice. It has six
questions and a shorter time window, so its absolute completion count is not a
controlled assistance-effect estimate. The packets reuse historical benchmark
contexts, not new independent financial reports. General learning across tasks
remains possible despite source separation.

## Analysis readiness and remaining boundary

The offline command checks assignment, version, source provenance and exact replay.
It retains rejected/blocked answers as unfinished deliverables, counts all offered
work, separates approval from release, marks missing blocks and treats duplicate
exports carefully. It creates official answer/scale scores, participant-level paired
B/C descriptions, elapsed interaction intervals, source revisits, grouping/admission
use, Raw TLX and separate custom-control items. Select-to-action duration is not
continuous reading time. A participant bootstrap is only a conditional descriptive
option for at least six complete pairs, never a powered superiority claim.

Every released answer can enter a blinded source-based adjudication packet, including
exact-match controls. Additional judgments need a reason and rater identity and do
not overwrite official scores. No independent adjudication has yet occurred.

**Participant results: unpopulated.** Repository inspection found prospective
materials and software/practice evidence, without documented institutional
permission, approved consent, or genuine participant records for analysis. The
investigator checklist specifies the remaining determination/consent, expertise,
tranche, assignment, privacy, accessibility and adjudication decisions. A future
participant-mode launch checks an operator-provided authorization record; the
software does not certify institutional approval. Alex may try investigator
practice immediately without representing it as independent participant evidence.

## Research decision

Keep the position-paper framing and the user-controlled review workflow as the
current direction. This package supports a reproducible system and **readiness to
study task feasibility**, not better human performance or lower workload. The
smallest next empirical step is an institutionally authorized formative tranche
using the fixed packets, with source-only performance, reconstruction reports and
review errors examined before designing an effectiveness study. If users mainly
solve the questions from scratch, improve task/draft feasibility as a new development
version rather than interpret B/C differences as evidence about oversight benefits.
