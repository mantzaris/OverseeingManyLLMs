# Internal author review: three strongest objections

This is an AI-assisted internal critique, not external peer review or human expert
validation. The active draft is a position paper. Existing primary-source reading
was rechecked only where the argument needed it.

## 1. This looks like ordinary queue engineering, not a research contribution

**Available response.** AgentGUI already provides concurrent desks, intervention,
artifact views and saved sessions (Sections 3.1–3.4); its Section 4.1 evaluates
trace comprehension with eight people. AGDebugger has message queues, pause/step,
editing and checkpoint forks (Sections 5.1–5.3). The manuscript now credits that
substantial overlap and does not infer missing safeguards from silence. Its
narrower position concerns individual output release under concurrent arrivals,
with an executable lifecycle and a comparison that keeps those safeguards common.
An ordinary well-engineered queue is the strong baseline B.

**Remaining gap.** No evidence establishes a unique interface mechanism or an
advantage over these systems. The workflow can be a defensible systems position,
not a new queueing algorithm. The B/C bundle needs interaction evidence before its
added controls justify a stronger contribution.

Sources: [AgentGUI, Sections 3–4](https://arxiv.org/html/2607.26300v1),
[AGDebugger, Sections 5–6](https://arxiv.org/html/2503.02068v1).
Prior interruption/queue comparisons remain in `../LITERATURE.md`; no new claim
about their full-text findings was added.

## 2. Perfect scripted review proves almost nothing about people

**Available response.** The 13,236 replayed events, stable active snapshots and
version-specific release checks establish the stated software behavior. A separate
approval preserves an inspection decision without releasing it; an active snapshot
prevents an arrival from changing its referent. The main text explicitly treats
release as a local application record, not a real financial transaction. All
conditions have the same safeguards. The scripted completion tie and pause-induced
waiting remain visible.

**Remaining gap.** The ideal script supplies corrections; it does not detect errors
or experience interruptions. Separate release could add needless effort. C could
distract or delay unrelated work. No review quality, perceived control or workload
benefit follows from protocol reliability. The current compact formative pilot
should expose misunderstandings and resumption failures before effectiveness is
estimated. The older interface-by-load design is not silently combined with it.

## 3. At 21% exact match, this may be manual financial QA with extra friction

**Available response.** Real tables, units, text and imperfect outputs expose this
problem instead of hiding it with clean fixtures. All original outputs remain.
The seven parser-lost displays do not raise exact match. The audit separates
substantive numerical/unit errors, optional-format flags and three unresolved
scoring disputes. The pilot packets were selected from public features, not model
success. Missing drafts stay visible.

**Remaining gap.** The audit cannot establish whether drafts help people. Independent
blinded adjudication is absent. The source-only block can diagnose source/calculation
difficulty but has different task/time allocations, so it cannot estimate an
assistance effect. If practice and authorized formative observations mainly show
reconstruction, improve task/draft feasibility under a new development version
before a larger interface study. Do not explain that outcome away as a UI problem.
