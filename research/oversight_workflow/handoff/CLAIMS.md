# Claims and their evidence boundary

All paths below are relative to the repository root. Historical measurements are
retained as recorded; no new experiment or participant result is introduced.

| Position or claim | Supporting evidence | What it does not establish |
|---|---|---|
| Concurrent answers can be individually reviewed and released without arrivals replacing the active artifact | `research/oversight_workflow/protocol.py`; recorded live demonstration and 41,722 active-snapshot checks in `research/oversight_workflow/EVALUATION.md` | User comprehension, attention or arbitrary distributed-system reliability |
| Every offered task, including paused and deferred work, stays accounted for | Protocol conservation checks; `artifacts/oversight_workflow/tables/pause_checkpoint.csv`; manuscript Figure 3 | Pausing improves throughput; the lower-load script instead waited longer |
| Decisions and releases identify an exact individual version | Immutable versions, stale-approval refusals, explicit release tests and saved event replay | That an approved answer is correct or that a separate release click is worth its effort |
| The application handles genuine imperfect model outputs over real financial sources | Frozen 24-context / 145-question manifest; 290 raw Qwen answers; official EM 61/290 | A financial-analyst field study or independent companies/reports |
| Seven lost answer displays are recoverable without new inference | `pilot_preparation/answer_audit.csv`, `empty_audit.json`, `pilot/adapter.py` | An accuracy gain: EM remains 61/290, joint answer/scale 59/290; historical 38 empty fields and pilot projection 31 are distinct |
| Low draft quality is not explained by optional evidence formatting | 157 evidence flags include 32 joint-correct cases; declared 22-case nonempty audit | Population-wide attribution of all 229 nonmatches; three disputes remain unadjudicated |
| The formative study is runnable | Frozen `pilot/manifest.json`, existing 44-check final browser dry run, identified exports and analysis | Participant observations, ethics approval, or powered effectiveness evidence |
| C offers additional ways to manage source-related work | Same B/C protocol and evidence; C adds source cards, session-aware Next and admission controls | An isolated grouping effect or superiority to B, AgentGUI or AGDebugger |
| Source-only tasks can reveal feasibility problems | Separate six-question/four-minute diagnostic with rotated position and disjoint sources | A controlled assistance-effect estimate against twelve-question/nine-minute B/C blocks |
| Users benefit in review quality, efficiency, control or workload | **No observations yet** | Must remain a hypothesis; ideal scripted correction and software fixtures cannot fill this gap |

The main manuscript's position is supported by a specified working system and
real-data software characterization. Its comparative human claim is a question,
not a result. The historical ideal script completes every condition and supplies
the correctness it is meant to test at the protocol boundary. It cannot tell us
whether people notice an error, reconstruct an answer or choose a useful session.
