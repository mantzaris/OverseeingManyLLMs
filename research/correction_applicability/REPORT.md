# Correction applicability: a completed development gate failure

The proposed correction-to-patch method **did not establish useful correction reuse**. Across two complete development versions it produced no supported reusable patch and committed no sibling revision. It therefore tied risk-ranked individual correction and the coverage-limited source-verification control. We stopped before the fresh-context comparison, as required by the development gate. This is a reproducible negative mechanism result, not an independently evaluated improvement.

The useful implementation is an inspection boundary, a bounded source-linked computation interface, scoped operation/fact/scale patch proposals, atomic candidate validation and rollback, and a local replay desk. Controlled cases exercise the protocol. They also show that successful execution and agreement with one inspected example can still permit a harmful semantic transfer.

## Continuity and experimental units

We started from clean main at pushed commit `570ae114`, fetched and checked main, and preserved the prior adaptive-correction-transfer package. Its held-out result remains individual 170/288 versus adaptive 156/288, with 14 final never-inspected repairs and 21 harms. No historical result, estimator, source snapshot or manuscript was edited. The initial protocol/source-audit milestone is `571e3702`.

This stage used **12 previously inspected training contexts and all 72 original questions**, the same saved v4 initial answers, and two fixed risk-ranked inspections per episode. Thirty-two questions have arithmetic annotations, 26 span, 12 multi-span, and two count. These categories are annotation types, not perfect runtime type labels. Both versions use the same source questions and must not be counted as 24 independent contexts or independent generation replicas.

The financial tables and paragraphs come from real reports in the pinned TAT-QA release. Questions and reference annotations are benchmark material. Agent assignments, inspection costs and direct annotation replacement are constructed/simulated. New interpretations and continuations were generated on the GPU. We did not observe humans, independently sample companies, or establish a benefit of a multi-agent architecture.

A deterministic source-pool audit excluded all 36 prior source contexts and exact repeated material, leaving 223 technically eligible unused test contexts. None was selected for a frozen evaluation or generated after the gate failed. Reliable source-report identifiers are absent. Even context-paired uncertainty is weaker than independent-report inference, and public-benchmark contamination remains possible.

## Method and fair controls

One inspected question reveals only its answer, scale and available derivation. It directly corrects that answer for every method. A separate continuation may explain that disclosure using the immutable source. The difference between the old and corrected computations proposes a fact-binding, operation/order or scale patch. The recipient must actually use the implicated component and retain its own supported periods, entity/metric anchor, units and unaffected bindings. Failed candidates leave the original untouched. Sibling reference answers are used only by offline scoring.

The seven methods share original answers, source access, the structured interface, model settings and exactly the same inspection sequence. Individual correction makes no sibling changes. Execution only evaluates extracted programs. Source verification independently rereads every eventual never-inspected question and applies the same public checks. Reattempt and coarse transfer use the same broad recipient schedule, respectively without and with acquired sibling feedback. Patch and no-applicability share identical donor requests; the latter removes recipient-semantic checks. Source verification selects its recipients without correction information and is independently runnable.

The coarse condition adapts the preceding memory-transfer mechanism to fixed inspections and the common interface; it does not reproduce the previous adaptive selector. No method is presented as a full PAL, Binder or SERAC reproduction. Initial representations are shared, and their cost is charged once in standalone cost comparisons. Individual correction does not need representation extraction. Policy-specific continuations are generated when prompts differ; only complete identical requests are cached.

## Why the gate failed

| Coverage | v1 | v2 |
|---|---:|---:|
| All original questions | 72 | 72 |
| Executable extracted records | 30 | 8 |
| Extracted records passing public contract | 0 | 1 |
| Acquired donor disclosures | 24 | 24 |
| Supported reusable patches | 0 | 0 |
| Accepted sibling patches | 0 | 0 |

v1 mixed valid arithmetic with malformed source IDs, unsupported numeric constants, row/metric mismatches, incorrect units and periods. The common strict contract accepted none. A uniform v2 refinement read metadata from the selected source cells and shortened the model schema. It reduced context-limit failures but generated only eight executable records. Sixty-one outputs returned no supported representation. Sixteen of the 24 fixed inspections concerned arithmetic questions, so the bottleneck is not explained solely by text questions. Within all 32 arithmetic questions, executable-record coverage fell from 24/32 to 8/32, with contract coverage 0/32 and 1/32. Of the 24 acquired donor pairs, 19 lacked a complete earlier or revised record; five failed period, percentage-expression or numeric-cell checks.

A post hoc metadata-only diagnostic on the unchanged v1 cell hypotheses recovers 12 public contracts. This identifies an interface/contract contribution to rejection, but does not replace the original v1 results or establish natural transfer. The shortened v2 prompt's poorer record coverage is retained as an unfavorable refinement outcome. One later structural guard rejects incomplete schemas before field access. Full saved-source replay preserves the original event reasons; the repaired API changed two explanations but no outputs or requests in a separate diagnostic.

The no-applicability ablation also produced zero revisions because patch construction failed upstream. Consequently its tie cannot validate recipient selection or show that the added predicates prevent natural collateral damage. A rule that never reaches the commit boundary has not solved applicability. The required gate conditions of natural commits, correction-dependent repairs and plausible net gain were unmet. We did not run the conditional 24-context/two-replica evaluation or the optional broad-regeneration patch ablation.

## What explains the controls' gains and harms?

Every final never-inspected gain from coarse transfer was in source context 0 and changed only the output scale to percent: four answers in v1 and two in v2. The source already marks the year headings with `%`. Thus source-unit interpretation is the nearest simpler explanation, not reuse of a newly discovered arithmetic rule. v1 ordinary reattempt also repaired one percentage-scale answer without a correction. Coarse transfer's extra benefit is not evidence for our patch mechanism.

The v1 coarse-transfer scored harm appended “from 2018 to 2019” to an explanatory span. We retain its official exact-match loss but do not assert that the longer phrase introduced a financial falsehood. v2 reattempt incurred that span mismatch, one wrong numeric change, and two thousand-to-million scale changes. The complete final-change audit is saved, not just favorable examples. Token F1 and exact scale help interpret these metric effects.

The historical audit separately retains genuinely wrong period substitution, ratio-versus-percentage-change confusion, and an unresolved 0.9-to-1.0 generation. It selects the first three helpful, harmful and score-tied events in fixed historical order. Source overlap does not establish a shared correctable cause. The current empirical gain concentration in one context further limits any broad claim.

## Synthetic protocol tests and failure boundary

Eleven authored cases, each with 32 bounded perturbation seeds and two conditions, produce 704 CPU-only rows. They are mechanism fixtures, not 704 independent empirical tasks. Operation/order repair can generalize across years while retaining recipient operands. A local fact correction that would change a requested comparison from 2017-2018 to 2017-2019 is rejected. Missing dependencies, changed source hashes and execution failures retain the old output. Shared amount-scale repair is exercised separately from a dimensionless ratio.

The checked method also retains a **harmful accepted patch**. A missing denominator is undetectable from a donor whose denominator is one. It matches the inspected annotation but changes an already correct recipient from 100% to 300%. The counterexample passes the implemented structural checks. Therefore the proven property is preservation of rejected/unaffected represented outputs and immutable sources, not semantic safety or universal correction applicability. A failed review can also leave an existing error unresolved; rollback must not be counted as completion.

## Claim-evidence assessment and recommendation

| Claim | Evidence and limit |
|---|---|
| The protocol can preserve rejected and unrelated represented outputs | Focused tests, synthetic traces and exact replay. This is a structural implementation property. |
| Acquired numerical annotations can always identify a reusable correction | Not supported. No natural patches; a constructed underdetermined formula harms a recipient. |
| Applicability checks improve TAT-QA correctness beyond individual correction | Not supported. Both versions tie it, with additional calls. |
| A development advantage over reattempt validates patching | False interpretation. v2 reattempt harms answers; patching makes no revisions. |
| Broader correction prompts can improve related outputs | Development evidence limited to scale corrections in one context; source already contains the units. |
| There is an independently evaluated methodological advance | Not established. The justified development gate prevented fresh evaluation. |

SERAC already treats edit scope and collateral changes, PAL/Binder already use executable reasoning, ExpeL already reuses experience, and dependency provenance already supports selective preservation. The proposed distinction required **correction-dependent additional accuracy under the purchased-feedback boundary**. It was not demonstrated.

Keep risk-ranked individual correction as the practical default. The next justified experiment is a small competence study of source-grounded unit and period bindings, with an independent source-reading baseline, before asking whether a verified annotation adds any information. The current protocol and counterexample are useful supporting evidence about failed correction transfer, but they should not become the paper's central improvement claim.
